# 예약 시각 30분 칸 선택 설계 (#963)

> **For**: 동방·장비 예약 폼의 시간 고르기를 만들거나 고치는 사람 (인간·AI).
> **You'll be able to**: 시간 칸이 어떻게 만들어지고, 어떤 칸이 왜 막히며, 누르면 무엇이 골라지는지 안다.

- 상위: [#963](https://github.com/skku-amang/main/issues/963) 예약 시각을 30분 칸을 눌러서 고르기
- 대체하는 것: [#888](https://github.com/skku-amang/main/issues/888) · [#936](https://github.com/skku-amang/main/pull/936) 15분 단위 휠

## 1. 왜

- 휠 두 개(시작·종료)를 돌려 맞추는 게 번거롭다는 부원 의견 ([Sentry WEB-4W](https://amang-23.sentry.io/issues/WEB-4W))
- 지금은 남의 예약과 겹치는 시간을 골라도 **저장을 눌러 거절당해야** 안다 ([Sentry WEB-4N](https://amang-23.sentry.io/issues/WEB-4N)). 처음부터 찬 시간이 보여야 한다
- 본보기: 네이버 예약의 시간 칸. 날짜를 고르면 시간 버튼이 줄지어 나오고, 찬 시간은 흐리게 막혀 있다

**성공**: 부원이 날짜 하나 누르고 쓸 칸들을 켜면 예약 시간이 끝난다. 길이 제한 없이 칸을 이어 붙여 늘릴 수 있다. 겹치는 시간 때문에 저장이 거절되는 일이 (동시에 두 사람이 고르는 경우 말고는) 없어진다.

## 2. 정한 것 (2026-11-25, 사용자 결정)

- **30분 단위만.** 더 잘게 고르는 접기 메뉴·직접 입력은 두지 않는다
- **휴대폰·PC 같은 방식.** PC용으로 따로 만들지 않는다. 주간 달력에서 끌어서 새 예약 만들기(WEB-4R)는 하지 않는다
- **동방·장비 둘 다.** 둘 다 같은 폼([RentalFormDialog.tsx](<../../../apps/web/app/(general)/(light)/reservations/_components/RentalFormDialog.tsx>))을 쓰고, 예약 하나가 장비 하나(`equipmentId`)를 잡으므로 막히는 시간 계산이 같다
- **자정 넘김: 날짜 하나만 고르고, 칸 목록을 다음날 06:00까지 이어 붙인다** (안 A). 날짜 범위 달력은 없앤다
- **찬 칸 정보는 폼이 직접 조회한다** (방식 1, 아래 §4)

## 3. 하지 않는 것

- 운영진 화면의 예약 폼 ([admin/rentals/_components/RentalFormDialog.tsx](<../../../apps/web/app/(admin)/admin/rentals/_components/RentalFormDialog.tsx>)) — 휠을 쓰지 않는 별도 폼이라 그대로 둔다
- 서버에 30분 단위 검사 추가 — 기존 비정렬 예약(§6)의 제목만 고쳐도 저장이 막히게 된다. 화면에서만 30분으로 고르게 한다
- 24시간 넘는 예약 — 운영 데이터 567건 중 0건 (2026-11-25), 최장 4시간
- "최근 업데이트" 글 — [#962](https://github.com/skku-amang/main/issues/962)에서 따로

## 4. 방식 비교

| 방식                          | 내용                                                                             | 판단                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **1. 폼이 직접 조회 (채택)**  | 고른 날짜·장비로 `GET /rentals?equipmentId=&from=<그날 00:00>&to=<다음날 06:00>` | 몇 달 뒤 날짜도 정확. 날짜를 바꿀 때 작은 요청 하나, 받은 날은 캐시                                                        |
| 2. 달력이 받아 둔 목록 재사용 | 뒤 화면 달력의 `rentalList`를 폼에 넘김                                          | 달력은 보고 있는 달 ±1달만 들고 있어, 그 밖의 날짜는 찬 칸이 **비어 보인다**. 기능 목적에 어긋남                           |
| 3. 서버가 빈 칸 계산          | 새 API                                                                           | 겹침 판단이 저장 검사([rental.service.ts:23](../../../apps/api/src/rental/rental.service.ts#L23))와 두 군데로 갈라짐. 과함 |

API의 기간 조회는 `endAt >= from AND startAt <= to`라서, 전날 밤에 시작해 그날 새벽까지 이어지는 예약도 받아진다.

## 5. 화면과 동작

```
[ 달력 — 날짜 하나 ]

11월 26일 (수)
[18:00][18:30][▒19:00▒][▒19:30▒]     ▒ = 찬 칸 (누를 수 없음)
[20:00][20:30][■21:00■][■21:30■]     ■ = 고른 칸
[■22:00■][■22:30■][23:00][23:30]
── 27일 (목) 새벽 ──
[00:00][00:30] … [05:30]
```

### 칸

- 칸 하나 = 그 시각부터 30분. 고른 날짜 00:00 ~ 23:30 (48칸) + 다음날 00:00 ~ 05:30 (12칸)
- **다음날 칸은 이어 붙여서만 고를 수 있다.** 다음날 새벽에 시작하는 예약은 그 날짜를 골라서 만든다
- 막히는 칸:
  - 고른 장비의 다른 예약과 30분 중 일부라도 겹치는 칸 (수정 중이면 자기 예약은 빼고 계산)
  - 이미 시작 시각이 지난 칸 (오늘 날짜일 때)
- 조회 중에는 칸을 누를 수 없게 하고 자리 표시만 보인다. 조회 실패 시 칸은 모두 열어 두고 "예약 현황을 못 불러왔어요" 한 줄 — 저장 때 서버가 겹침을 거절하므로 안전하다

### 누르기

칸마다 켜고 끈다. 고른 칸은 늘 이어져 있어야 해서(끊긴 예약은 없음) 양 끝에서만 붙이고 뺀다. 시작·끝 두 번 누르기로 처음 만들었다가, 한 번 고른 뒤 늘리려면 처음부터 다시 골라야 해서 "1시간까지만 되는 것 같다"는 문제로 바꿈 (2026-11-25, 사용자 결정)

1. 아무것도 안 골랐을 때 누르면 → 그 칸 하나(30분)가 골라짐
2. 고른 칸 바로 뒤·바로 앞 빈 칸을 누르면 → 붙음. 계속 누르면 길이 제한 없이 늘어난다
3. 고른 칸의 맨 앞·맨 뒤 칸을 누르면 → 빠짐. 하나 남은 칸을 누르면 비워짐
4. 고른 칸 가운데는 누를 수 없다 (빼면 예약이 끊김)
5. 떨어진 빈 칸을 누르면 → 그 칸부터 새로 고름
6. 찬 칸·지난 칸으로는 붙일 수 없다. 다음날 새벽 칸은 바로 뒤일 때만 붙고, 맨 앞 칸을 빼서 다음날부터 시작하게 되는 경우엔 빠지지 않는다

### 처음 값

- 달력 빈 칸을 눌러 열었을 때: 그 시각부터 1시간 (지금과 같음)
- 예약하기 버튼: 다음 정시부터 1시간 (지금과 같음)
- 위 처음 값이 찬 칸과 겹치면: 아무것도 고르지 않은 상태로 연다
- 수정: 기존 예약 그대로 (§6, §7)
- 처음 고른 칸이 보이게 칸 목록을 스크롤해 둔다

### 그 밖

- 칸 목록은 정해진 높이 안에서 세로로 스크롤한다 (60칸을 다 펼치면 폼이 너무 길다)
- 칸 목록에는 테두리를 두지 않고, 아래에 시간·총시간 요약 줄도 두지 않는다 — 고른 칸 색과 "다음날 새벽" 구분 줄로 충분하다 (2026-11-25 사용자 결정)
- 장비나 날짜를 바꾸면: 지금 고른 범위가 새 날짜·장비에서 막히면 선택을 지운다. 날짜만 바꾸고 안 막히면 같은 시각을 유지한다
- 저장할 때 고른 칸도 없고 그대로 둘 기존 예약 시각(§6)도 없으면 "시간을 골라주세요"
- 화면낭독기: 칸은 버튼, `aria-pressed`로 골림 표시, 찬 칸은 `disabled` + "예약됨" 이름

## 6. 30분 단위가 아닌 기존 예약

운영 예약 567건 중 70건이 14:15처럼 30분 단위가 아니다 (2026-11-25, 앞으로 잡힌 것은 1건).

- 이런 예약을 수정 화면에서 열면 칸 위에 `지금 14:15 ~ 15:15` 한 줄을 보이고, 칸은 아무것도 골라지지 않은 상태로 둔다
- 칸을 건드리지 않고 저장하면 원래 시각을 그대로 보낸다 (제목·참여자만 고치는 경우)
- 칸을 누르면 30분 단위로 새로 고르게 된다
- 칸은 안 건드리고 날짜만 바꾸면 같은 시각(14:15 ~ 15:15)을 새 날짜로 옮긴다. 새 날짜에서 겹치면 선택을 지운다 — _만드는 사람 판단_

## 7. 이미 시작했거나 끝난 예약 수정 (사용자 결정, 안 "가")

수정 버튼은 예약이 진행 중이거나 끝난 뒤에도 참여자·운영진에게 보인다 ([RentalDetailModal.tsx](<../../../apps/web/app/(general)/(light)/reservations/_components/RentalDetailModal.tsx>)). "6시까지 하고 조금 더 쓰기"([#888](https://github.com/skku-amang/main/issues/888) 인터뷰)를 칸 한 번으로 할 수 있게 한다.

| 예약 상태 (지금 시각 기준)     | 시간 고르기                                                                                                                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 아직 시작 전                   | 새 예약과 같음 (§5)                                                                                                                                                                                                 |
| **진행 중** (시작 ≤ 지금 < 끝) | **시작 고정.** 달력은 바꿀 수 없다. 칸을 누르면 끝만 바뀐다 (늘리기·줄이기). 끝으로 고를 수 있는 칸은 지금 이후이면서 시작 뒤 첫 찬 칸 전까지. 시작 시각이 30분 단위가 아니어도 그대로 두고 끝만 30분 칸으로 고른다 |
| 이미 끝남                      | 달력·칸 대신 `11월 26일 14:00 ~ 16:00` 글자만. 제목·참여자만 고칠 수 있고, 저장 시 원래 시각을 보낸다                                                                                                               |

- 진행 중일 때 시작 시각 이전 칸은 자기 예약 부분이라도 고른 색으로만 보이고 누를 수 없다
- 상태는 폼을 연 순간 기준으로 정한다 (열어 둔 사이에 시각이 바뀌어도 폼 동작은 그대로. 저장은 서버가 판단)

## 9. 만드는 사람에게 맡기는 것

- 칸 만들기·막힌 칸 계산·누르기 규칙은 화면과 떼어 순수 함수로 두고 단위 테스트한다. 위치는 `packages/shared-types/src/rental/rental-time.ts` 옆 (이미 vitest가 있음). 날짜 계산은 한국 시각 기준
- 칸 목록 컴포넌트 이름·파일 위치, 스크롤 높이, 칸 색 (디자인 기준은 [apps/web/AGENTS.md](../../../apps/web/AGENTS.md#디자인-기준))
- 폼 전용 조회 훅은 기존 `useRentals`를 그대로 쓴다 (`equipmentId`·`from`·`to` 지원)
