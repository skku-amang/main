# 이메일 인증·비밀번호 찾기 설계 (#528)

> **For**: 이메일 인증과 비밀번호 찾기를 만들거나 고치는 사람 (인간·AI).
> **You'll be able to**: 인증번호가 어디서 만들어져 어디에 저장되고 언제 사라지는지, 인증 안 된 회원은 어떻게 비밀번호를 찾는지 안다.

- 상위: [#528](https://github.com/skku-amang/main/issues/528) 비밀번호 찾기
- 메일 발송 수단: [ADR-0004](../adr/0004-email-provider-resend.md) (Resend)

## 1. 왜 인증부터인가

지금 등록된 이메일은 본인 것인지 확인한 적이 없다. 확인 없이 메일로 비밀번호를 찾게 하면, 가입 때 오타로 남의 주소를 적은 경우 그 주소의 주인이 계정을 가져갈 수 있다. 그래서 **인증된 메일로만** 비밀번호를 찾는다.

| 회원              | 비밀번호를 잊으면                                                  |
| ----------------- | ------------------------------------------------------------------ |
| 이메일 인증함     | 로그인 화면 → "비밀번호 찾기" → 메일로 받은 인증번호 → 새 비밀번호 |
| 이메일 인증 안 함 | 운영진이 회원 관리에서 재설정 링크를 만들어 카톡으로 전달          |

- 새로 가입하는 사람: 가입 화면에서 메일 인증번호를 넣어야 가입 신청이 된다
- 기존 회원: 로그인하면 "이메일을 인증하면 비밀번호를 직접 찾을 수 있어요" 배너가 뜬다 (닫으면 7일 동안 숨김). 내 정보 수정 화면에서도 인증할 수 있다. 정기모임 공지는 운영진이 한다

## 2. 데이터

- `User.emailVerifiedAt DateTime?` — 인증한 시각. `null`이면 미인증
- 운영진이 회원의 이메일을 바꾸면 `emailVerifiedAt`을 `null`로 되돌린다

인증번호와 재설정 링크는 잠깐만 살아 있으면 되므로 DB가 아니라 Redis에 둔다.

| 키                                    | 값                       | 수명   |
| ------------------------------------- | ------------------------ | ------ |
| `email-code:{용도}:{이메일}`          | 인증번호 해시, 틀린 횟수 | 10분   |
| `email-code-cooldown:{용도}:{이메일}` | (있으면 재발송 대기 중)  | 60초   |
| `email-code-hourly:{이메일}`          | 한 시간 동안 보낸 횟수   | 1시간  |
| `password-reset-token:{토큰 해시}`    | 회원 id                  | 24시간 |

- 용도: `signup`(가입) · `verify`(기존 회원 인증) · `reset`(비밀번호 찾기)
- 인증번호: 6자리 숫자 (`crypto.randomInt`). 해시(sha256)만 저장하고 비교는 `timingSafeEqual`
- 5번 틀리면 인증번호를 지운다 → 다시 받아야 한다
- 한 이메일로는 60초에 한 번, 한 시간에 5번까지 보낸다
- 맞으면 바로 지운다 (한 번만 쓸 수 있음). 가입만 예외로, 회원이 저장된 뒤에 지운다 — 닉네임 중복 등으로 저장이 실패해도 같은 번호로 다시 가입할 수 있다. 같은 번호로 동시에 가입해도 이메일이 unique라 한 건만 저장된다
- 이메일은 소문자로 받아 저장한다 (`emailField`). 대소문자만 다른 주소가 다른 계정이 되지 않게
- 재설정 링크 토큰: 32바이트 무작위(base64url). 한 번 쓰면 지운다

## 3. API

| 메서드·경로                                 | 로그인 | 하는 일                                                                                                |
| ------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| `POST /auth/email-code`                     | 불필요 | 가입용 인증번호 발송. 이미 쓰는 이메일이면 거절 (가입과 같은 오류)                                     |
| `POST /auth/signup`                         | 불필요 | 본문에 `emailCode` 추가. 맞으면 `emailVerifiedAt = now()`로 가입                                       |
| `POST /users/me/email-verification`         | 필요   | 내 이메일로 인증번호 발송                                                                              |
| `POST /users/me/email-verification/confirm` | 필요   | 인증번호 확인 → `emailVerifiedAt = now()`                                                              |
| `POST /auth/password-reset/request`         | 불필요 | 인증된 회원이면 인증번호 발송. 응답은 항상 같다                                                        |
| `POST /auth/password-reset/confirm`         | 불필요 | 이메일·인증번호·새 비밀번호 → 비밀번호 변경, 모든 기기 로그아웃                                        |
| `POST /auth/password-reset/link`            | 운영진 | 본문 `{ userId }` → 재설정 토큰 `{ token, expiresAt }`. 화면이 `/password-reset?token=…` 주소를 만든다 |
| `POST /auth/password-reset/token`           | 불필요 | 링크 토큰·새 비밀번호 → 비밀번호 변경, 모든 기기 로그아웃                                              |

비밀번호를 바꾸면 그 회원의 로그인 세션을 모두 지운다. 누군가 이미 로그인해 있었다면 쫓겨난다.

## 4. 메일

- 보내는 주소: `아망 <no-reply@amang.json-server.win>`
- 제목: `[아망] 인증번호 123456` — 알림 미리보기에서 번호가 바로 보이게
- 본문: 용도별 한 줄 안내 + 인증번호 + "10분 안에 입력하세요" + "요청한 적 없다면 무시하세요"
- 발송은 `MailService` 한 곳에서만 한다. `RESEND_API_KEY`가 없으면(로컬) 보내지 않고 로그에 남긴다

### 스테이징 봇

스테이징 트래픽 봇은 `@amang.staging.json-server.win` 주소로 가입한다. 받는 메일함이 없는 주소라 실제로 보내면 반송이 쌓이고 무료 한도(하루 100통)를 쓴다.

- 스테이징 설정([kustomization.yaml](../../../infra/k8s/api/overlays/staging/kustomization.yaml))에만 `MAIL_TEST_DOMAIN=amang.staging.json-server.win`과 `MAIL_TEST_CODE`를 둔다. 봇도 같은 값을 읽는다
- 받는 주소가 그 도메인이면 메일을 보내지 않고, `MAIL_TEST_CODE`를 맞는 인증번호로 받아 준다
- 번호를 봉인하지 않고 그대로 둔다. 이 번호로 인증할 수 있는 건 메일함이 없는 그 도메인 주소뿐이라, 알려져도 남의 메일을 인증할 수 없다
- 프로덕션에는 두 값이 없다. 실수로 들어가도 그 도메인 주소만 영향을 받는다 (실제 회원은 그 도메인을 쓰지 않음)
