# 업데이트 소식 글 쓰기

> **For**: 부원이 알아야 할 기능을 추가하거나 고친 사람 (개발자·AI).
> **You'll be able to**: 홈 "업데이트 소식"과 `/updates`에 보일 글을 사진과 함께 올린다.

글은 코드와 같이 배포된다. 운영에 올라가는 순간 글도 보이므로, **기능 PR에 글도 같이** 넣는다. 부원이 알아챌 만한 변화일 때만 쓴다 (내부 정리·사소한 수정은 쓰지 않음).

## 1. 글 파일

`apps/web/content/updates/<날짜>-<짧은-이름>.md` 하나를 만든다. 파일 이름이 상세 페이지 주소(`/updates/<파일 이름>`)가 된다.

```md
---
title: 예약 시간을 30분 칸으로 골라요
date: 2026-11-25
href: /reservations/clubroom
---

첫 문단이 홈 카드의 한 줄 설명이 된다.

![사진 설명](/updates/2026-11-25-reservation-slots/1.webp)

- 목록·링크 같은 md 문법을 쓸 수 있다
```

- `title`·`date`(YYYY-MM-DD)는 꼭 적는다. 틀리면 빌드가 실패한다 ([lib/updates.ts](../../apps/web/lib/updates.ts))
- `href`는 상세 페이지의 "써 보러 가기"로 갈 화면. 없으면 빼도 된다
- 부원이 읽는 글이라 쉬운 말로, 짧게. 의견을 준 부원이 있으면 고마움도 적는다

## 2. 사진

- `apps/web/public/updates/<파일 이름>/1.webp`처럼 글마다 폴더 하나에 둔다
- **webp, 폭 1200px 이하**로 줄여서 넣는다 (레포에 계속 쌓이므로). 휴대폰 폭 스크린샷이면 한 장에 수십 KB
- 본문에 `![설명](/updates/...)`로 넣는다. 설명은 화면낭독기가 읽으니 무엇을 보여 주는지 적는다

## 3. 확인

- 로컬에서 홈 맨 아래 "업데이트 소식" 카드(최신 3개), `/updates` 목록, `/updates/<파일 이름>` 상세에 보이는지 본다
- 날짜가 마지막으로 읽은 글의 날짜보다 뒤면 카드에 "새 글"이 붙는다 (상세를 열면 그 날짜까지 지워짐). 다시 보려면 브라우저 저장소의 `amang:updates-seen-at`을 지운다
