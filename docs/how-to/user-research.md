# 부원 의견 모으고 결정까지 잇기

> **For**: 부원 인터뷰를 하거나, 그 결과로 다음 작업을 정하는 사람 (개발자·기획자·인터뷰 대리인·AI).
> **You'll be able to**: 인터뷰를 하고, 기록을 어디에 어떻게 남길지, 그것이 어떻게 로드맵과 GitHub 이슈로 이어지는지 안다.

개발자가 더 이상 주 사용자가 아니기 때문에, "무엇을 만들지"는 개발자의 감이 아니라 **부원의 실제 이야기**에서 시작한다.

> 용어: 이 문서의 "부원 의견"은 인터뷰·대화로 들은 이야기 전체를 말한다. "피드백"은 [용어집](../reference/glossary.md)상 녹음본 피드백 시스템의 이름이라 쓰지 않는다.

## 1. 어디에 무엇을 적나

```text
인터뷰 1회 ──→ 노션 인터뷰 DB: # 인터뷰(원문) + # 인사이트   [비공개]
                 │ 인사이트 → 해결책 후보
                 ▼
              노션 Task DB (아이디어 + ICE 점수 + 근거 수)   [비공개]
                 │ 우선순위
                 ▼
              docs/explanation/roadmap.md (Now/Next/Later)    [공개]
                 │ 진행 결정
                 ▼
              GitHub 이슈                                     [공개]
```

| 무엇 | 어디 | 공개 |
|---|---|---|
| 인터뷰 원문과 인사이트 | 노션 인터뷰 DB (인터뷰 1회 = 1행) | ❌ |
| 아이디어 | 노션 Task DB | ❌ |
| 로드맵 | [roadmap.md](../explanation/roadmap.md) | ✅ |
| 작업 | GitHub 이슈 | ✅ |

인터뷰 기록은 실명과 다른 사람 이야기가 섞여서 비공개로 둔다. 공개하면 부원이 솔직하게 말하지 않는다. 노션 접근은 루트 [AGENTS.md](../../AGENTS.md)의 외부 도구 컨텍스트를 따른다.

## 2. 인터뷰하기

원칙은 *The Mom Test*(Rob Fitzpatrick) 하나다: **미래·의견이 아니라 과거 행동을 묻는다.**

| ❌ 피할 질문 | ✅ 대신 |
|---|---|
| "동방 예약 기능 쓸 거예요?" | "지난번 동방 쓸 때 어떻게 했어요?" |
| "이 기능 있으면 좋겠어요?" | "그때 뭐가 제일 귀찮았어요?" |
| "홈페이지 어때요?" | "이번 주에 홈페이지 몇 번 들어갔어요? 뭐 하러요?" |

- "~하면 좋겠다"는 요청이 나오면 **"그게 없어서 지난번에 어떻게 했어요?"** 로 한 번 더 판다. 지금 쓰는 우회 방법(카톡, 엑셀 등)이 진짜 경쟁 상대다.
- 메모는 아무 데나 빠르게 적는다. 정리는 인터뷰가 끝난 뒤에 한다.
- 설문(구글폼)은 의견만 모이고 정확도가 낮아서 보조로만 쓴다. 사이트 안의 "의견 보내기"로 들어온 내용도 같은 흐름으로 정리한다.

## 3. 인터뷰 정리하기

AI에게 "인터뷰 정리해줘"라고 메모를 넘기면 아래를 한다. 사람이 직접 해도 순서는 같다.

1. **노션 인터뷰 DB에 1행 추가.** 화자·날짜·수집 방법·영역을 채운다. 본문은 두 칸이다.
   - `# 인터뷰`: 들은 말 그대로. 앞에 (행동)/(불편)/(요청)/(긍정)을 붙인다. 실제로 한 일인 (행동)이 (요청)보다 믿을 만하다.
   - `# 인사이트`: 원문에서 끌어낸 결론을 한 문장씩. 각 인사이트 아래에 연결된 아이디어·이슈와 다음에 물을 것을 적는다.
2. **아이디어 연결.** 인터뷰 행의 "관련 아이디어"에 Task DB 항목을 연결한다. 없으면 새로 만든다. Task DB의 "근거 수"(몇 번의 인터뷰에서 나왔나)가 자동으로 늘어나며, ICE의 확신도를 매길 때 참고한다.
3. **로드맵 점검.** 근거가 쌓여 우선순위가 바뀌면 [roadmap.md](../explanation/roadmap.md)를 고친다. 근거는 익명으로 한 줄만 적는다 (4절).
4. **이슈 만들기.** 바로 고칠 수 있는 것은 GitHub 이슈로 만들고 `from: user-feedback` 라벨을 붙인다. 본문에는 익명 근거만 적고 노션 링크는 붙이지 않는다 (외부에서 열리지 않음).

## 4. 공개 문서의 익명화 규칙

로드맵·이슈처럼 공개되는 곳에 부원 의견을 옮길 때:

- 이름 대신 "부원", "팀장", "운영진", "신입" 수준까지만 쓴다.
- 기수·세션·직책을 **조합해서 한 사람으로 좁혀지면 쓰지 않는다.**
- 다른 부원이나 간부를 평가하는 내용은 옮기지 않는다.

## 5. 하지 않는 것

이슈 템플릿, 노션↔GitHub ID 강제 연결, 날짜가 있는 로드맵, 별도 리서치 도구 도입은 하지 않는다. 필요해지면 그때 가볍게 추가한다.
